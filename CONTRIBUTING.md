# Contributing

Start with a project you use. A reproducible bug, a clearer example or a small working fix is a useful contribution.

1. Read that project's README and contribution guide. Its instructions and license take precedence over these defaults.
2. Check existing issues and pull requests. For a large change, open an issue describing the problem before building it.
3. Make one focused change on a branch. Keep unrelated formatting, generated files and dependency updates out.
4. Run the project's documented checks. Include the command and result in the pull request; explain anything you could not verify.
5. Describe what changes for the user. Include a before/after image for visual changes, and an undo step for changes to live services.

## Bugs and ideas

Report an issue in the affected repository. Include the version, operating system, steps, expected result and actual result. Remove credentials, private URLs and personal data from logs and screenshots.

For an idea, describe the task you are trying to complete and the smallest change that would help. A proposed feature is not a delivery promise.

## Working together

Be direct and kind. Critique the work, respect people's time and keep discussions relevant. Do not post harassment, private information or credentials. See [working together](CODE_OF_CONDUCT.md) for conduct expectations and a private route for concerns.

## Releases

Follow the project's release process. A passing build proves the build; verify a deployed change at its public address before calling it live. Preserve a working undo path.

See [studio standards](docs/STANDARDS.md) for the defaults we use when building and maintaining projects.
